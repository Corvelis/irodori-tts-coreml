# 音声の登録、再利用、削除

[サンプル操作](SAMPLES.md) · [SDK API](API.md)

「登録」は、参照音声から話者の特徴を作って合成に使う処理です。追加学習やモデル重みの更新は行いません。参照音声の文字起こしを入力するAPIもありません。

## 入力する音声

まず自分の声など利用許可のある、1人が明瞭に話す3〜10秒程度の音声から試してください。BGM、複数人の声、長い無音、強いクリッピングは避けます。これは入力を選ぶ目安で、特定の声への完全な一致を保証するものではありません。

`ReferenceAudio.read(_:)` はAVAudioFileで読める音声を48 kHz・モノラル・Float32へ変換します。拡張子だけで対応を判断せず、実際に読み込めるか検証します。サンプルの録音出力は48 kHz・モノラル・PCM16 WAVです。

受付範囲は0.16〜120秒ですが、最低長ちょうどの音声は変換後の潜在フレーム数不足で拒否される場合があります。録音は自動で120秒に停止する実装ではありません。長すぎた場合も停止後の検証でエラーになります。

## 選択と特徴生成の違い

サンプルの「音声を選ぶ」と録音停止は、音声を読み込み検証し、アプリ内に保存して選択状態にする操作です。**特徴量の準備は「準備」または「生成して再生」で行います。** UIの「登録しました」は、この選択・保存を完了した意味です。

SDKを直接使う場合は、モデル準備後に登録します。

```swift
import Foundation
import IrodoriTTS

func selectVoice(engine: IrodoriEngine, referenceURL: URL?) async throws {
    // engine.prepare(modelDirectory:) を完了してから呼ぶ。
    let registration = try await engine.registerReference(referenceURL)
    print("参照準備(ms):", registration.milliseconds,
          "再利用:", registration.cacheHit)
}
```

`nil` を渡すと現在の参照を外し、参照なしで合成します。ディスクキャッシュや元ファイルの削除ではありません。別のURLを登録すれば声を切り替えられますが、複数話者の一覧や選択状態の永続化はSDK利用側で実装します。

サンプル `0.2.1` 以降は、参照音声・指示・固定seed・モデルの版を名前付きで保存できます。参照音声は設定専用のコピーとして保持します。生成結果の「この声に固定する」は実際のseedと条件を引き継ぎ、「この音声を参照に登録」は完成音声を新しい参照として取り込みます。[保存と呼び出しの手順](SAMPLES.md#気に入った声に固定する)を参照してください。

## 処理時間が0 msになる理由

サンプルは時間を小数点なしで表示します。再利用によって短時間で終わった処理が、丸められて0 msと表示される場合があります。

- 同じengineに同じ変換済み音声を登録すると、保持中の特徴を再利用します。音声の読込・変換・ハッシュ計算は実行します。
- 別の起動でも、音声内容と関連モデル情報に対応するディスク上の特徴キャッシュがあれば再利用します。
- モデル準備の0 msは、同じengineに同じモデルがロード済みの場合です。

時間だけで判断せず、`ReferenceRegistration.cacheHit` または画面の「キャッシュ」を確認してください。キャッシュはモデルを低精度化して作り直す仕組みではありません。

## 保存されるもの

サンプルの保存先は、アプリのApplication Support内の `IrodoriSample` です。端末・サンドボックスによって絶対パスが変わるので固定文字列で扱わないでください。

| 保存物 | 場所 | 保持・削除 |
|---|---|---|
| 取り込んだ音声・録音 | `IrodoriSample/References/` | 選び直した過去コピーも残る。サンプルの削除ボタンでまとめて削除 |
| 保存した声の設定 | UserDefaultsの `voicePresets` と `References/` 内の専用コピー | 名前・モデルの識別情報・指示・固定seed・任意の参照。設定は個別削除でき、参照の一括削除では参照付きの設定も削除 |
| 選択状態 | UserDefaultsの `referencePath` | サンプルの削除ボタンで解除 |
| 参照特徴 | Caches内 `irodori-reference-coreml-v1/` | `clearReferenceCache()` で削除 |
| 生成WAV | `IrodoriSample/generated.wav` | 次の生成成功時に上書き。参照削除では残る。再起動時のUIには再表示しない |
| モデル原本コピー | `IrodoriSample/Models/` | 参照削除では残る |
| コンパイル済みモデル | Caches内 `irodori-coreml-v3/` | 参照削除・releaseでは残る |

SDKの `registerReference` 自体は元音声ファイルをコピーしません。音声コピーと選択状態の保存はサンプルの処理です。SDKの登録はアプリ再起動後に自動復元されません。保存したURLを使って再登録してください。

## 削除を実装する

`try await engine.clearReferenceCache()` は、このengineの保持中の参照と、そのアプリが使う参照特徴ディスクキャッシュ全体を消します。元音声は消さないため、アプリ自身が作成した音声コピーと選択状態も別途削除します。[サンプルのdeleteReference](../Examples/Shared/SampleModel.swift)が実装例です。

サンプルの「保存した声を管理」は個別の設定と専用の参照コピーを削除します。「登録音声とキャッシュを削除」は取り込み・録音・生成音声から登録した参照と、参照付きの保存設定をまとめて削除し、参照なしの設定は残します。

CLIは同じユーザーのCaches領域を共有します。他のengineがメモリに保持する参照までは削除しないため、複数engineを使うアプリでは利用を止めてから削除を管理してください。現在のCLIには音声削除コマンドはありません。

音声登録・合成は端末内で実行します。モデル取得時には通信し、ユーザーがWAV共有を選んだ場合は選んだ共有先へ渡します。録音や特徴キャッシュを配布リポジトリへ含めないでください。
