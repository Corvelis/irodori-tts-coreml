# iPhone / Macサンプルの使い方

[README](../README.md) · [English](SAMPLES.en.md) · [音声登録の詳細](VOICE_REGISTRATION.md) · [困ったとき](TROUBLESHOOTING.md)

対象: `0.2.1` のiPhone / Mac共通SwiftUIサンプル。

同じSwiftUI画面をiPhoneとMacで使います。文章入力を中心に、モデル・声の設定と生成結果を分けた画面です。Macは広いウィンドウで2列、iPhoneは縦に並びます。ライト・ダークモードに対応します。

**このサンプルは句読点で文章を分割せず、入力全体を一度に合成し、完成WAVを再生します。** SDKの句読点分割とPCMチャンク通知は、独自アプリへ組み込むための任意機能として残っています。

## 起動する

リポジトリのルートで次を実行します。プロジェクトは生成済みなのでRubyスクリプトの実行は不要です。

```sh
open Examples/IrodoriSamples.xcodeproj
```

| 対象 | Scheme | Run Destination |
|---|---|---|
| Apple Silicon Mac | `IrodoriMac` | My Mac |
| iPhone実機 | `IrodoriiOS` | 接続したiPhone |

対象targetの **Signing & Capabilities** で自分のTeamを選び、Bundle Identifierを自分の一意な値に変更します。iPhoneを開発用に接続し、Xcodeが求める設定を完了してRunします。詳細はAppleの[実機での実行手順](https://developer.apple.com/documentation/xcode/running-your-app-on-simulated-or-physical-devices)にあります。速度や音声出力の確認には実機を使用してください。

速度比較では **Product → Scheme → Edit Scheme… → Run → Build Configuration** をReleaseにします。同じ端末、モデル、参照音声、文章、電源・熱状態で測定してください。

ソースとモデルは別配布です。サンプルアプリをビルドしただけでは、別配布のモデルはアプリに入りません。生成にPython、ONNX Runtime、ASR、LLMは不要です。

## アプリアイコン

ミント色の波形を使ったアイコンをiPhone・Mac両方へ設定済みです。Xcodeから通常どおりビルドすると適用されます。iPhone用は不透明な正方形、Mac用は背景が透過した角丸タイルです。画像と差し替え手順は[アイコンについて](APP_ICON.md)を参照してください。

## 最初は参照音声なしで試す

1. 初回画面の「はじめにモデルを準備」で標準版または軽量INT8版を選び、「モデルをダウンロード」を押します。取得済みフォルダを使う場合は「モデル」の「フォルダを選ぶ」で取り込めます。
2. 「声と話し方」が「参照なし」で、話し方の入力欄を空欄にします。初回は録音や声の許可スイッチを操作する必要はありません。以前の登録音声がある場合は削除ボタンで参照なしにできます。
3. 「読み上げるテキスト」の初期文章で「生成して再生」を押します。「準備」を別途押す必要はありません。
4. モデル準備と全文生成が終わると再生が始まり、RTF・生成時間・音声長と「生成した音声」が表示されます。再生ボタンで一時停止・再開、「WAVを保存」で保存できます。

iPhoneでは画面を縦にスクロールして設定欄へ進みます。Macではウィンドウが広いと文章・再生が左、モデル・声の設定が右に並びます。最初の生成で待ち時間が長くても、反復時の速度と分けて判断してください。

## 1. モデルを取得する

初回は画面上部にモデル取得の案内を表示します。標準FP32版が初期選択で、軽量INT8版は選んだときだけ取得します。Hugging FaceのログインやURL入力は不要です。取得する版の容量、必要OS、初回準備を含む空き容量の目安を表示します。Wi-Fi接続をおすすめします。

1. 「取得するモデル」で版を選び、「モデルをダウンロード」を押します。
2. 取得容量・割合と、ダウンロード／整合性検証の状態を表示します。100%でも検証が完了するまで待ってください。
3. 完了すると、そのモデルを自動で選択します。文章を入力して「生成して再生」を押します。初回にはCore MLのコンパイルと端末向け最適化が必要です。

取得中はアプリを開いたままにしてください。iPhoneの自動ロックは取得中だけ抑制し、終了・中断時に元へ戻します。別アプリへ切り替えると取得を中断し、戻ってから「再開する」で再試行できます。バックグラウンドで取得を継続する方式ではありません。

通信エラーや中断後、アプリを再起動した場合も再開ボタンを表示します。取得済みファイルはサイズとSHA-256を再確認して再利用し、中断した個別ファイルは先頭から取得します。「取得データを削除」はその中断分だけを削除します。別モデルを取得する場合は、先に中断分を再開するか削除してください。

空き容量が足りない場合はファイル取得前に案内します。表示する容量は目安で、Core MLの端末向けキャッシュ量は端末・OSで変わります。ネットワークから再取得できるアプリ内モデルフォルダはバックアップ対象から外します。

### 取得済みフォルダを取り込む

1. モデル配布フォルダをMacまたはiPhoneのFilesから選べる場所へ用意します。圧縮ファイルなら先に展開します。iPhoneではFinderのファイル共有でサンプルへコピーすると、「ファイル」→「このiPhone内」→「Irodori Core ML」から選択できます。
2. 「フォルダを選ぶ」（選択後は「モデルを変更」）で `manifest.json` と各モデルのすべての `.mlpackage` が並ぶ親フォルダを選びます。単体の `.mlpackage` やZIPを選ばないでください。
3. コピーとハッシュ検証が終わるまで待ちます。外部の元フォルダは残り、アプリ内にコピーされます。

モデルは [Hugging Face](https://huggingface.co/AILogDev/Irodori-TTS-v4.1-Small-MF-CoreML)、SDK・サンプルは [GitHub](https://github.com/Corvelis/irodori-tts-coreml) から取得します。直接取得する場合は「取得するモデル」で現行版または軽量INT8版を選び、「モデルをダウンロード」を押します。独自の配布先は「URLからダウンロード」にmanifest URLを指定できます。

Hugging Faceのリポジトリ全体を取得した場合、現行版はルート、軽量版は `int8` フォルダを選びます。サンプルは選択したフォルダをコピーするため、通常は「モデルをダウンロード」で使用する版だけを取得してください。取得した軽量版の保存先では `manifest.json` が直下にあります。[配置の詳細](HUGGINGFACE.md)を参照してください。

現行版約2.99 GB / 軽量INT8版約1.96 GBに加え、アプリ内コピーとコンパイルキャッシュが必要です。選び直した過去のモデルコピーも残るため、容量に余裕を持たせてください。「モデルを管理」から不要な保存済みモデルを削除できます。

## モデルを切り替える

「保存済みモデル」で取り込み済み・取得済みのモデルを選びます。モデル名とmanifestに記載された容量を表示します。切り替え時にはファイルを検証し、以前のCore MLセッションを解放します。登録音声と話し方の指示は保持し、次の生成時に選択したモデルを準備します。過去の生成結果の表示はクリアされます。

軽量INT8版にはiOS 18 / macOS 15以降が必要です。旧OSでは現行版を使用してください。初回コンパイルの影響を避けて速度を比較するには、それぞれ2回以上生成します。

## 保存済みモデルを削除する

「モデル」→「モデルを管理」で保存済み一覧を開き、ゴミ箱ボタンから確認して削除します。このアプリ内の取り込みコピー・取得済みモデルが対象で、選択元の外部フォルダ、登録音声、書き出したWAVは削除しません。使用中モデルを削除するとセッションを解放し、他の保存済みモデルがあれば選択します。すべて削除すると初回のモデル取得案内に戻ります。

削除するのはモデル原本です。Core MLコンパイル・端末向けキャッシュはOSの管理も受けるため、モデル削除と同時にすべてのキャッシュ容量が解放されるとは限りません。

## 2. 声を登録する

1. 利用できる声であることを確認し、「利用できる声を登録」をオンにします。
2. 「音声を選ぶ」で既存ファイルを取り込むか、「録音する」で3〜10秒程度話し、「録音を停止」を押します。マイク許可を求められたら許可します。MacはXcodeで署名付きRunを使用し、OSの入力機器が目的のマイクであることを確認してください。
3. 「登録音声あり」になったら、「モデル」欄の「準備」または「生成して再生」を押します。ここでモデルのロードと参照特徴の生成・再利用を行います。

音声を選ばず「参照なし」のままでも生成できます。一度登録した声を外すには削除ボタンを使います。気に入った声はseedと指示をまとめて名前付きで保存できます。

### 気に入った声に固定する

1. 「声と話し方」→「生成のseed」で「ランダム」を選んで試します。
2. 気に入った音声が出たら、「生成した音声」の「この声に固定する」を押します。その音声で実際に使ったseed、モデル、参照音声、話し方の指示を引き継ぎます。数字を入力する必要はありません。
3. 「声と話し方」の「保存」を押し、名前を付けます。モデルのmanifest、固定seed、指示と、参照ありなら専用の音声コピーを保存します。モデル本体は複製しません。
4. 「保存した声を選ぶ」から呼び出せます。同じモデルが端末にある場合は自動で選び直します。モデルを削除していたり別の版しかない場合は、同じモデルの再取得・取り込みを案内し、別モデルへ黙って置き換えません。

「固定」ではseedを直接入力できます（0〜4294967295）。隣のシャッフルボタンは別のseedを選び、次の「生成して再生」で試します。「ランダム」に戻すと生成ごとにseedを選びます。選択モード、固定seed、指示と参照の選択、保存した声は再起動後も保持します。声の利用許可スイッチは起動ごとに確認してください。

seedは声のIDではありません。同じ条件で再現しやすくなりますが、文章、参照、指示、モデルの版や端末・OSが変わると声や抑揚も変わります。別の文章でも声質を保つには、同じ参照音声と矛盾しない指示を使ってください。生成した音声を参照にしたい場合は、利用許可を確認し「この音声を参照に登録」を押します。参照条件が変わるため、次の生成を聞いてから保存してください。

「保存した声を管理」では個別に削除できます。設定専用の参照コピーも削除しますが、元の録音・取り込み元、モデルと書き出したWAVは残ります。「登録音声とキャッシュを削除」は参照音声を含む保存した声もまとめて削除します。

## 3. 読み上げて保存する

1. 「読み上げるテキスト」に文章を入力します。
2. 「生成して再生」を押します。「準備」を省いた場合も、この操作の中で準備します。
3. 入力全体を合成し、WAVの完成後に再生します。句読点による分割や先行再生は行いません。長文は全文の生成時間ぶん待つ方式です。初回のコンパイルや特殊化は、さらに待ち時間が長くなることがあります。
4. 「生成した音声」の再生ボタンで一時停止・再開・もう一度再生できます。波形の棒は生成PCMから計算した32区間の振幅、進捗はプレイヤーの再生位置です。
5. 「WAVを保存」で出力を保存します。iPhoneは共有画面の「ファイルに保存」、Macは保存ダイアログで保存先と名前を指定します。アプリ内の `generated.wav` は次の生成成功時に上書きされるため、残す場合は別の場所へ保存してください。

「停止」は合成中または再生中に表示します。再生を止め、合成Taskをキャンセルします。実行中のCore ML処理は終了まで待つため、次の操作が可能になるまで時間がかかる場合があります。途中のPCMは再生しません。

全文一回の合成にはモデルの上限があります（BOSを含む本文256トークン・latent 768 frames）。文字数だけで判定できる上限ではありません。上限超過はエラーを表示し、黙って分割・切り捨てをしません。文章を短くして生成してください。URL・Markdown等の読み上げ用整形は有効です。

## 4. 数字を読む

| 表示 | 意味 |
|---|---|
| RTF | 合成処理時間÷出力音声長。低いほど速い |
| 生成時間 | 本文の合成にかかった時間（秒） |
| 音声の長さ | 出力音声の秒数 |
| モデル設定内の「準備」 | モデルロード。同じモデルを保持していると0 ms |
| モデル設定内の「参照」 | 音声読込・変換と参照特徴の準備。再利用時は「キャッシュ」表示 |

RTFと生成時間は、ASR、LLM、モデル準備、参照登録、WAV保存と実スピーカーの遅延を含みません。短文は固定費の影響が大きいため、長文と同じRTFにはなりません。SDKの `firstPCMMilliseconds` は生成側のPCM準備時刻で、全文完成を待って再生するこの画面の再生開始時刻ではありません。

## 5. 削除と再起動

「登録音声とキャッシュを削除」は、このサンプルが保持する録音・取り込みコピーすべて、設定専用の参照コピーと参照特徴キャッシュを削除します。参照音声を含む保存した声の設定も削除し、参照なしの設定は残します。選択元の音声、モデル、生成済みWAVは削除しません。

モデルと選択した音声は再起動後も保持します。声の許可スイッチは起動ごとにオフに戻るため、登録音声を使うときは再確認してオンにしてください。

## 声・話し方の指示

共有サンプルの「声と話し方」の入力欄に日本語の短い説明を入力します。参照音声あり・なしの両方で使用でき、空欄で無効になります。指示は端末の設定に保存されます。SDKでは `synthesize(text, caption: instruction)` を使用し、サンプルはさらに `splitSentences: false` を指定します。詳しくは[API](API.md#声話し方の指示voice-design)を参照してください。

## 音声の透かし

生成音声にはAudioSealの透かしを標準で付与します。再生音声と保存WAVは同じPCMです。RTFには透かしの処理時間も含みます。[付与・検出の使い方](WATERMARK.md)を参照してください。
