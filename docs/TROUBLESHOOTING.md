# トラブル対処とFAQ

[導入](GETTING_STARTED.md) · [サンプル操作](SAMPLES.md) · [音声登録](VOICE_REGISTRATION.md)

## 導入・モデル

| 症状・表示 | 確認すること |
|---|---|
| `No such module 'IrodoriTTS'` | Package.swiftのあるルートを追加したか、IrodoriTTS productがアプリtargetにリンクされているか |
| 署名・Teamのエラー | targetのSigning Teamと自分のBundle Identifierを設定。モデルのエラーではない |
| `Prepare a model first` | 同じengineでprepare完了後に登録・合成しているか。release後は再準備が必要 |
| ファイルが見つからない / `Missing model file` | 15個のmlpackageが並ぶ親フォルダを指定。一部パッケージだけ、ZIP、古いONNX構成を選ばない |
| `This is not an Irodori Core ML bundle` / `Invalid FP32 component metadata` | 対応する一式を使用。異なる版のモデル・sidecarを混ぜない |
| `Model checksum mismatch` / `Downloaded file failed verification` | 欠落・途中取得・変更を確認。metadataを書き換えて通さず固定revisionから再取得 |
| `Destination already exists` | 完成した出力先は上書きしない仕様。既存モデルをverifyして利用するか、新しいフォルダを指定 |
| 取得に失敗する | [モデル取得ガイド](HUGGINGFACE.md)のmanifest URL、ネットワーク、空き容量を確認。途中で失敗した場合は同じURLと保存先で再試行 |

初回コンパイルには時間がかかります。状態欄とXcode/CLIログを確認し、毎回フォルダを取り込み直すことは避けてください。再取り込みは別コピーを増やします。

## 音声登録・録音

| 症状・表示 | 確認すること |
|---|---|
| 音声選択・録音ボタンが押せない | 声の許可スイッチ、処理中/録音中でないかを確認。許可は起動ごとに再確認 |
| マイクにアクセスできない | OSのマイク許可、NSMicrophoneUsageDescription、MacのAudio Input権限を確認 |
| `Reference audio must be between...` / `at least four latent frames` | まず3〜10秒の明瞭な音声で確認。極端に短い音声や120秒超は避ける |
| ファイルが開けない・変換できない | 拡張子ではなく実データを確認。サンプルで録音したPCM WAVで切り分け |
| 参照の処理が0 ms | 再利用と整数表示の丸めが考えられる。「キャッシュ」表示を確認。元音声の削除を示す値ではない |
| 登録を消したのにWAVが残る | 削除ボタンは登録音声と特徴だけを消す。生成WAVと選択元の音声は残る |

## 再生・文章・品質

| 症状・表示 | 確認すること |
|---|---|
| 「生成して再生」が押せない | モデル選択、本文が空欄でないこと、処理中/録音中でないことを確認 |
| 「文章がモデルの上限を超えています」 | サンプルは全文を一度に合成するため、文章を短くして再生成。句点を追加しても分割されない。文字数とトークン数は同じではない |
| 句点の後でも音が出ず、全文生成を待つ | 現在のサンプルの方式。途中PCMの先行再生は行わない。初回コンパイル・特殊化も待ち時間に影響する |
| 再起動したら声の利用許可を求められる | 登録音声は保持されるが許可スイッチは起動ごとにオフになる。「利用できる声を登録」をオンにする |
| 「WAVを保存」や結果の数値が見つからない | 生成成功後に表示される。iPhoneでは文章入力の下へスクロール。再起動時は前の生成結果の表示を復元しない |

`No speakable text` は、空欄や整形後に読む文字が残らなかった場合です。URLは「リンク」、Markdownリンクは表示文字を残し、括弧は種類に応じて除去・読点化します。送った内容は `SynthesisResult.preparedText` で確認できます。

漢字の読みの誤りは、記号除去だけでは修正されません。「々」は保持しますが、SDKには日本語の読み辞書やルビ指定APIはありません。読みが確定している単語はアプリの読み上げ用テキストでかなに置き換える方法があります。画面用文章とは分けて管理してください。

音が出ない場合は、結果のaudioSeconds、音量・出力先、プレイヤーのエラーを確認します。SDK単体は自動で再生しません。保存したWAVを別プレイヤーで再生できれば、再生経路を先に確認できます。「最初のPCM」が短くても、スピーカー開始の速さを確認したことにはなりません。

長文や反復後に音が崩れた場合は、次を記録して切り分けます。

1. 同じ文章・同じ合成モードで再現し、保存したWAVでも崩れるか確認する。GUIサンプルは `splitSentences: false`、SDK/CLIの既定値は文分割ありなので、比較時はモードを揃える。
2. 通知順のPCMと完成PCMが一致するか確認する。CLIは自動で照合します。アプリでは古いリクエストのチャンク混入、複数プレイヤー、PCM形式を確認します。
3. 発生前の短文の回数、声の切り替え、停止操作、LLMの同時使用を記録する。
4. 必要なら参照なし・別の許可済み参照で比較する。比較中にモデル精度やステップ数を変えない。

再現する場合は、文章・参照条件・保存WAVとエラーを揃えて、下の問い合わせ先へ報告してください。

## 速度・RAM・容量

同じengineを再利用し、モデル検証・ダウンロード・録音準備を発話の待ち時間から外します。不要なengineを複数作らず、チャンクコールバックでは重い処理を行わないでください。Releaseビルド、初回/反復、短文/長文を分けて比較します。

約2.99 GBは配布ファイルのサイズです。実行時RAMやキャッシュ込みのディスク容量とは異なります。使用量は端末と処理条件によって変わります。長文の完成PCM、再生待ちバッファ、複数モデル、LLMの同時実行も使用量に影響します。

releaseはセッションを解放しますが、OSのメモリ回収の時刻やRSSがすぐ一定値まで下がることを保証しません。ディスク容量を戻す場合は[保存場所](VOICE_REGISTRATION.md)を確認し、アプリを停止してから自分のアプリの不要なコピーを対象にします。参照削除ではモデルコピーは消えません。

## 問い合わせに添える情報

端末/OS、コード版、モデル版とmanifest、Debug/Release、通常/rawと文分割の有無、初回/反復、再現文章、参照の秒数・形式、同時に動かした処理、エラー全文、CLIのレポートを用意すると切り分けやすくなります。[GitHub Issues](https://github.com/Corvelis/irodori-tts-coreml/issues)で報告してください。

音声・文章・ログには個人情報が含まれる場合があります。公開Issueでは公開してよい再現材料だけを添付し、登録音声や個人の絶対パスをそのまま載せないでください。

## モデルのダウンロードが中断した

ネットワーク接続を確認して「ダウンロードを再開」を押します。アプリの再起動後も再開できます。検証済みのファイルは再利用し、取得途中のファイルは先頭から取り直します。iPhoneでは取得中に別アプリへ切り替えると中断するため、完了まで画面を開いておいてください。

空き容量の案内が出た場合は「モデルを管理」で不要なモデル、または「取得データを削除」で中断分を削除してから再試行します。モデル容量とは別にCore MLのコンパイル・端末向けキャッシュが必要です。
